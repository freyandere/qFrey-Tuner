# Разбор поведения qBittorrent после настройки

Расчёт находится в `optimizer/calculator.py`, применение и проверка — в
`optimizer/optimization_cycle.py`. В Results добавлен отчёт по фактическим
показаниям до/после; назначение изменённых настроек выводится отдельно от
наблюдаемого результата. Интерфейс сохраняет существующий английский язык.

## Какие эффекты стоит проверять

| Настройки | Что могут изменить | Подходящая проверка |
| --- | --- | --- |
| Лимиты скачивания/отдачи | Пропускную способность и конкуренцию с другим трафиком | Средняя и медианная скорость; отдельно задержка сети без нагрузки и под нагрузкой |
| Число соединений, скорость новых подключений, backlog | Число подключений и скорость их установления, расход ресурсов | Подключённые пиры, разгон; отдельно входящая доступность, CPU/RAM |
| Upload slots | Распределение отдачи между пирами | Стабильная отдача при наличии спроса, скорость отдельных получателей |
| Очередь и число активных торрентов | Конкуренцию нескольких загрузок/раздач | Несколько обычных, не принудительно запущенных торрентов: время в очереди, общая скорость, распределение скорости |
| Кэш, OS cache, coalescing, preallocation, I/O threads | Использование памяти, подготовку файлов, чтение/запись | Дисковая задержка и очередь, память, ошибки I/O, скорость длительной нагрузки |
| Send buffer и его пороги | Подготовку данных для отдачи и использование памяти | Стабильная раздача, память и задержка чтения |
| TCP/µTP, шифрование | Совместимость с пирами и поведение транспорта | Скорость и подключения, задержка сети под нагрузкой; шифрование не доказывает обход DPI |
| DHT/PeX/LSD | Источники адресов пиров | Время первых подключений; число DHT-узлов само по себе не показатель ускорения |
| Порт и привязка интерфейса | Входящие подключения и выбранный путь трафика | Внешняя проверка порта и отдельная проверка поведения при потере VPN |
| Anonymous mode | Передаваемую идентифицирующую информацию | Проверка конфигурации/протокола; скорость не подтверждает приватность |
| Super seeding | Первичное распространение раздачи | Отдельный сценарий нового релиза; приложение автоматически этот параметр не меняет |

Семантика буферов и I/O описана в [руководстве libtorrent](https://www.libtorrent.org/tuning-ref.html).
В libtorrent 2 [убран прежний дисковый кэш](https://www.libtorrent.org/upgrade_to_2.0-ref.html):
приложение уже исключает соответствующие настройки при применении.
Доступные поля и методы нужно сверять с версией [Web API qBittorrent](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API).

## Что добавлено сейчас

- Медиана скачивания и отдачи всей сессии.
- Разброс скорости: стандартное отклонение / средняя скорость. Ниже — ровнее показания; это не универсальная оценка качества.
- Доля отсчётов с нулевой скоростью. Это доля показаний, а не точная длительность остановок и не диагноз причины.
- Среднее число подключённых сидов и пиров на основном участке замера.
- Доля отсчётов, где у наблюдаемых торрентов был `stalledDL`, `stalledUP`, `error` или `missingFiles`.
- Реальные изменённые значения и их назначение; пропущенные при применении настройки.
- Явные границы измерения и отсутствие данных в старых результатах.

Новые состояния сохраняются в существующей истории `ramp_trace` JSON эксперимента.
Для официального образа пиры и состояния относятся к тестовому торренту;
для ручного замера — к исходному активному набору. Скорость всей сессии может
включать посторонние торренты, поэтому эти области прямо указаны в отчёте.
Прогрев исключён из новых агрегатов. Неизвестные значения не заменяются нулями.

## Что требует отдельного замера

CPU/RAM и дисковые показатели нужно собирать на машине qBittorrent: локальные
показания компьютера с Tuner не подходят для удалённого NAS/seedbox.
Задержку сети, входящий порт и защиту VPN текущий тест не измеряет.
Один ISO не проверяет очередь нескольких торрентов; случайная отдача во время
скачивания не заменяет тест сидирования с реальными получателями.

До/после показывает наблюдаемое изменение всего набора настроек, но не вклад
каждой настройки. Для выводов нужны повторные сопоставимые испытания с учётом
смены пиров, состояния кэша и спроса на отдачу. Текущие 50%/90% разгона относятся
к собственной опорной скорости каждого прогона, а не к общему абсолютному порогу.
